# 마비노기 모바일 음성 채팅

말하면 인게임 채팅으로 바로 나간다. 트레이에 상주하는 창 프로그램.

## 시작하기

**먼저 게임에서 준비할 것이 있다.** 이걸 켜지 않으면 채팅을 보낼 수 없다.

1. 마비노기 모바일 PC 클라이언트를 켠다
2. 설정에서 **MM AI 에이전트 활성화** 를 켠다
3. 이 토글을 켜면 게임이 조작용 프로그램(`MabinogiMobile_CLI.exe`)을 깔아
   준다. 그래야 이 프로그램이 게임과 말을 주고받을 수 있다

그 다음 **`실행.bat`** 을 두 번 누른다.

**첫 실행은 시간이 걸린다.** 파이썬과 필요한 것들을 받아오기 때문이다.
한 번만 겪으면 되고, 그 다음부터는 바로 뜬다.

| 단계 | 받는 양 | 비고 |
|---|---|---|
| 파이썬 | 45 MB | 이 프로그램 폴더 안에만 들어간다 |
| 패키지 | 약 400 MB | 음성 인식에 쓰는 것들 |
| GPU 가속 | 550 MB | NVIDIA 그래픽카드가 있을 때만. 물어본다 |
| 모델 | 0.5~3 GB | 창에서 고른 것. 아래 「모델 고르기」 참고 |

이미 파이썬이 깔려 있어도 건드리지 않는다. `runtime\` 폴더 안에 따로 두므로
기존 파이썬과 섞이지 않는다.

오류를 눈으로 보고 싶으면 `콘솔로_실행.bat` 쪽을 쓴다. 설치만 다시 하려면
`설치.bat` 이다.

## GPU 가속

**NVIDIA 그래픽카드가 있으면 GPU 로 돌리는 편이 몇 배 빠르다.** 다만 그러려면
`cuBLAS` 라는 라이브러리가 필요한데, 대부분의 PC 에는 없다. CUDA 툴킷을 깐
사람에게는 이미 있지만 그런 경우는 드물다.

설치할 때 그래픽카드가 보이면 **550 MB 를 받을지 물어본다.** 그때 넘겼거나
나중에 마음이 바뀌면 `GPU로_바꾸기.bat` 을 한 번 실행하면 된다.

없어도 프로그램은 **CPU 로 잘 돌아간다.** 대신 큰 모델은 말보다 인식이 한참
늦으므로 `small` 을 쓰는 게 낫다. 창이 그 사실을 알려 준다.

> **`cublas64_12.dll 을 찾을 수 없습니다` 라는 창이 떴다면**
> 1.0.0 판에서 나던 문제다. 1.0.1 부터는 이 창이 뜨지 않고, GPU 를 쓸 수
> 있는지 먼저 확인한 뒤 안 되면 조용히 CPU 로 내려간다. 새 판으로 바꾸고,
> GPU 로 쓰고 싶으면 `GPU로_바꾸기.bat` 을 실행한다.

## 모델 고르기

창의 **모델** 칸에서 고르고 **내려받기** 를 누르면 진행률이 보인다. 받은
모델은 `models\<이름>\` 에 한 벌로 남아 다음부터 그대로 쓴다.

| 모델 | 크기 | 한국어 | 쓸 곳 |
|---|---|---|---|
| tiny / base | 0.1 GB | 나쁨 | 시험용 |
| small | 0.5 GB | 보통 | GPU 가 없을 때 |
| medium | 1.5 GB | 좋음 | 무난 |
| **large-v3-turbo** | 1.6 GB | 매우 좋음 | **대부분 이걸 권한다** |
| large-v3 | 3.1 GB | 가장 좋음 | VRAM 3GB 이상 여유가 있을 때 |

첫 실행에 이 PC 형편을 보고 하나를 골라 준다. GPU 가 없으면 `small`,
VRAM 여유가 3GB 이상이면 `large-v3`, 그 사이면 `large-v3-turbo` 다.

GPU 가 없으면 큰 모델은 말보다 인식이 늦어 대화에 쓰기 어렵다. 그럴 때는
`small` 로 내려야 한다.

## 배포본 만들기

```
python build_dist.py
```

`dist\mabi-voice-chat-<판번호>.zip` 이 나온다. **30KB 남짓**이다.
`runtime\` 과 `models\` 는 넣지 않기 때문이다. 받는 사람이 `실행.bat` 을
누르면 자기 PC 에 맞는 것이 알아서 들어간다.

들어가는 것은 `build_dist.py` 의 `FILES` 목록이 전부다. 개인 설정
(`settings.json`), 보낸 말 기록(`sent.log`), `runtime\`, `models\` 는
이름이 스치기만 해도 멈추도록 막아 두었다.

판번호는 `core.py` 의 `VERSION` 한 곳에서 고친다.

## 쓰는 법

- **말하면 나간다.** 확인 단계는 없다.
- **Win+F9** 로 듣기를 켜고 끈다. 다른 게임이나 프로그램이 앞에 있어도
  먹힌다. 창 포커스와 무관하게 키 상태를 직접 읽기 때문이다.
- 창을 **닫거나 최소화하면 작은 표시창**으로 내려간다. 끄려면 트레이
  메뉴의 **종료**.
- 자리를 비울 때는 꼭 듣기를 끈다. 켜 둔 채로 두면 방 안의 모든 말이
  공개 채팅에 올라간다.

### 작은 표시창 (오버레이)

디스코드 오버레이처럼 항상 위에 떠 있는 137x38 짜리 창이다. 점 색과
글자로 듣는 중인지 아닌지 보이고, 옆의 얇은 막대가 지금 들어오는 음량이다.

| 조작 | 하는 일 |
|---|---|
| 끌기 | 자리를 옮긴다. 옮긴 위치를 기억한다 |
| 왼쪽 클릭 | 큰 창을 다시 연다 |
| 오른쪽 클릭 | 듣기를 켜고 끈다 |

전체화면을 **독점 방식**으로 쓰는 게임 위에는 뜨지 않는다. 테두리 없는
창 모드(borderless)면 잘 보인다.

### 단축키 바꾸기

**설정** 탭의 **키 바꾸기** 를 누르고, 원하는 조합을 그대로 누른다.
Win 을 섞어도 잡힌다. Esc 로 취소되고 8초 뒤 자동으로 취소된다.
**바꾸면 그 자리에서 바로 적용된다** — 다시 실행할 필요가 없다.

쓸 수 있는 키는 F1~F12, A~Z, 0~9, `space`, `insert`, `scrolllock`,
`pause` 이고, 여기에 Win · Ctrl · Shift · Alt 을 섞을 수 있다.
`settings.json` 의 `hotkey` 를 직접 고쳐도 된다.

#### 단축키가 게임 안에서 안 먹힐 때

단축키를 잡는 방법은 두 가지이고, 순서대로 시도한다.

1. **RegisterHotKey** — 운영체제가 조합을 먼저 가로채서 우리에게 알려준다.
   어느 창이 앞에 있든, 게임이 그 키를 쓰든 상관없다. Win 조합을 써도
   시작 메뉴가 열리지 않는다. 기본이 이쪽이다.
2. **키 상태 직접 읽기** — 1번이 실패했을 때만 쓴다. 조합이 이미 다른
   프로그램에 등록되어 있으면 1번이 실패한다. 이 방식은 **게임이 관리자
   권한으로 돌고 우리가 아니면 막힌다.**

그래도 안 먹히면 `관리자로_실행.bat` 으로 띄운다. 게임과 같은 권한이 되어
2번 방식도 뚫린다. UAC 창이 한 번 뜬다.

창 아래 기록에 `단축키 Win+F9 등록됨` 이 찍혔는지 보면 어느 쪽이 쓰이는지
알 수 있다.

처음이라면 **연습 모드**를 켜고 한 번 돌려 본다. 인식은 하지만 채팅으로
보내지 않으므로, 말이 어디서 끊기는지 안전하게 확인할 수 있다.

## 창에 있는 것

위쪽은 늘 보이는 상태 칸이다. 지금 듣는 중인지, 어떤 단축키를 쓰는지,
그리고 음량 막대가 있다. 막대의 **초록은 지금 들어오는 소리**, **주황 선은
말소리로 인정하는 문턱**이다. 초록이 주황을 넘으면 녹음이 시작된다.

아래는 **기록** 과 **설정** 두 탭이다.

| 설정 항목 | 설명 |
|---|---|
| 마이크 | 장치를 바꾸면 즉시 다시 연다 |
| 모델 | 고르고 내려받는다. 아래 「모델 고르기」 참고 |
| 단축키 | 키 바꾸기 버튼을 누르고 원하는 조합을 누른다 |
| 민감도 | 주변 소음의 몇 배를 말소리로 볼지. 게임 소리에 헛발질하면 올린다 |
| 말끝 기다림 | 이만큼 조용하면 한 마디가 끝난 것으로 본다. 말이 잘리면 늘린다 |
| 연습 모드 | 인식만 하고 보내지 않는다 |

설정은 `settings.json` 에 저장되고, 보낸 말은 `sent.log` 에 남는다.

## 알아 둘 제약

게임 쪽 제약이라 우회할 수 없는 것들이다.

- **채팅 한 줄은 50자.** 넘치면 여러 줄로 쪼개 1.2초 간격으로 보낸다.
- **채널을 고를 수 없다.** API 에 채널 지정이 없어서, 게임에서 열어 둔
  채팅창으로 나간다. 길드로 말하려면 게임에서 채널을 길드로 바꿔 둔다.
- **`/` `#` 로 시작하는 말은 게임이 명령으로 보고 거절한다.** 그래서 첫
  글자가 그 둘이면 떼어내고 보낸다.
- 게임이 꺼져 있거나 **MM AI 에이전트 활성화**가 꺼져 있으면 보낼 수 없다.

## 걸러내는 것

자동 전송이라 헛것이 나가지 않도록 아래는 버린다.

- 0.4초 미만 (기침, 마우스 클릭)
- 위스퍼가 침묵에 붙이는 헛문장 ("구독과 좋아요" 등)
- 같은 글자만 반복되는 인식 실패
- 5초 안에 같은 말이 두 번 잡힌 중복

## 채팅이 두 번씩 나갈 때

프로그램이 두 개 돌고 있는 것이다. 이제는 두 번째 실행이 스스로 거절하고
안내창을 띄우지만, 그래도 의심되면 남아 있는 것을 확인한다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe' OR Name='pythonw.exe'" |
  Select-Object ProcessId, CreationDate, CommandLine
```

`mabi_voice.pyw` 가 두 줄 이상 나오면 묵은 쪽을 `Stop-Process -Id <번호> -Force`
로 내린다. 창이 안 보여도 배경에서 듣고 있을 수 있다.

## 구성

```
mabi-voice-chat/
├─ core.py              목소리 감지 · 인식 · 전송. UI 를 모른다
├─ models.py            모델 목록 · 내려받기 · 위치 관리
├─ mabi_voice.pyw       창과 트레이
├─ build_dist.py        배포용 zip 만들기
├─ requirements.txt
├─ setup.bat            파이썬과 패키지를 runtime\ 에 들인다
├─ setup_gpu.bat        GPU 가속 라이브러리(550MB)를 넣는다
├─ 실행.bat             이걸 누른다 (콘솔 없이)
├─ 설치.bat             setup.bat 을 부르는 껍데기
├─ 콘솔로_실행.bat      오류를 볼 때
├─ 관리자로_실행.bat    단축키가 끝까지 안 먹힐 때
├─ GPU로_바꾸기.bat     setup_gpu.bat 을 부르는 껍데기
└─ tools/
   ├─ voice_chat.py     같은 엔진의 콘솔판
   └─ stt_test.py       마이크·인식만 시험 (--list, --scan)
```

만들어지는 것 (모두 저장소에 올리지 않는다)

| 이름 | 무엇 |
|---|---|
| `runtime\` | 전용 파이썬과 패키지. 약 440MB |
| `models\` | 받아 둔 음성 인식 모델 |
| `settings.json` | 내 설정 |
| `sent.log` | 보낸 말 기록 |
| `dist\` | 배포용 zip |

## 쓰는 모델

faster-whisper 를 CUDA `int8_float16` 으로 쓴다. float16 보다 메모리를 절반만
쓰고 정확도 차이는 작다. 게임이 VRAM 을 4GB 넘게 쓰는 일이 흔해서 이렇게 골랐다.
CUDA 가 안 되면 CPU 로 자동 내려간다.

파이썬은 `runtime\` 에 따로 둔다. 공식 내장판(embeddable)에는 tkinter 가
없어서 창을 띄울 수 없으므로, tkinter 가 포함된 python-build-standalone
빌드를 쓴다.
